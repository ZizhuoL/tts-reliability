# Pre-Final-Evaluation Delivery Audit

Audit date: 2026-10-20. This audit follows the explicit requirements in [PROJECT_BRIEF.md](../PROJECT_BRIEF.md) and its ten deliverables in Section 10. It reviewed existing code, records, and artifacts and checked selected file identities, analysis completion markers, and documentation links. It did not rerun passed tests, load models, start GPU work, or read or hash the sealed final texts. The only file written during that audit was this document.

**Conclusion at the time: no new substantive defect was found in the completed scope, but the project could not yet be considered complete.** There was actual evidence for seed183's full continued-training epoch, full course validation, six-system development evaluation, and analysis. Seed184 was still running; the final protocol was not frozen, and independent final evaluation and the final synthesis of findings remained unfinished. A prepared runner, templates, temporary test output, or development reports could not substitute for those missing results.

This is a historical audit. Later completion evidence is recorded in [the final delivery audit](delivery_audit_final.md).

## 3. Other Explicit Requirements and Boundaries

### Justified Problem, Reliable Baseline, and Method Selection

Literature findings and project observations were recorded separately. Initial reference-format sensitivity was not counted as a training improvement. Formal A used a fixed recording and standardized reference text; length ranges came from the real training distribution. EOS, output limits, and context limits were recorded separately. The complete formal baseline did not establish stable overall length-specific degradation, so length-weighted C was deferred. The brief allowed evidence-based changes of direction: **not running C did not omit a mandatory experiment**. Ordinary continued training, the LM-prefix strategy, and sentence-splitting engineering comparisons had all run, with single-factor and combined differences reported separately.

Selection at this stage used only the six seed183/A development systems. BNoLM met the overall/short/long WER and cap/error conditions. The candidate was recorded but not finally frozen. Seed184 could only assess sensitivity, not justify changing the primary seed or candidate. Several paired confidence intervals for the short development group crossed zero; passing the point-estimate rule did not prove statistical noninferiority.

### Correctness and Earlier Review Findings

[code_review.md](code_review.md) records historical read-only findings, not a current list of unresolved defects. Reading the implementation and existing tests confirmed:

- Sentence splitting protected common abbreviations, initialisms, and closing quotation marks after terminal punctuation; `tests/test_evaluation.py` contained regression coverage.
- Training-resume compatibility checks included `grad_clip` and `device`; `tests/test_training.py` checked rejection after changing gradient clipping.
- Non-resume training refused to overwrite existing protected run artifacts; the same test file covered this behavior. Effective training-exposure analysis separately identified and excluded discarded rollback branches.
- The final runner's role-file rewrite issue after an interrupted finalization was fixed: identical content was reused and differing content rejected. Coordinator records showed 10 temporary-fixture regressions passing. Those tests still did not replace a real final run.

These tests were not rerun in this audit. Historical `STATUS.md` session records documented 41 passed tests, 6 subsequent strategy-cost tests, and 10 passing final-runner tests. At audit time, `.pytest_cache/lastfailed` was empty and nodeids contained 48 entries. **The number of cache entries is not evidence that 48 tests passed during this audit**, and no such claim is made. Actual starter MPS cache checks were fixed-length numerical comparisons with EOS deliberately suppressed, not complete-utterance quality tests.

### Data Separation, Statistics, and Failure Denominators

Independent natural-text preparation included source snapshots, exact/constituent-sentence/8-gram deduplication, and development/final separation records. Course development data participated in checkpoint selection; full validation on 9,756 examples was not an independent final test. Unknown pretraining coverage of the starter/acoustic models was not assumed absent.

Existing analysis used a shared normalizer and preserved raw ASR, S/D/I, errors, and stopping reasons. It used text-cluster bootstrap stratified by length, keeping both generation seeds in the same text cluster. All six development cells were scorable, so common-success and whole-utterance-deletion sensitivity results happened to agree. That conclusion could not be carried into final evaluation if observations were missing. Deletions do not automatically establish omissions, nor insertions repetition.

The sole B development audio longer than 30 seconds crossed Whisper chunking windows, introducing an ASR-path confound for that sentence-splitting comparison; the report disclosed it. Actual split subsets, per-segment budgets, and pauses were recorded. Splitting was not described as an equal-total-budget ablation, and timing differences alone did not establish a speedup.

### Local Execution, Actual Costs, and Retained Failures

Training code supported only local CPU/MPS execution; manifests recorded the current device split and local environment. Local execution records contained no evidence of paid APIs, cloud GPUs, publication, or coursework submission, and this audit performed no external operations. This was not a comprehensive network audit of all historical machine activity.

Seed183's two OOM events, discarded updates, recovery probes, effective compute, within-step total time, and unknown full-run wall time were accounted for separately. The scope of observed MPS memory, process RSS high-water marks, and system-wide swap was explicit. The development wrapper's exit127 remained in the [finalization reconciliation](../results/analysis/development-execution-reconciliation/incident.json). Later read-only prerequisite checks returning exit0 and valid artifacts did not rewrite the original pipeline exit code as zero.

## 5. Nature of the Remaining Gaps

The core unfinished work was the running seed184 pipeline, subsequent freezing and independent final evaluation, and integration of final results into delivery. These prevented declaring the Goal fully delivered but were not technical blockers requiring fresh user authorization.

Two further issues were disclosure boundaries rather than newly discovered runtime failures: there was no independent full reconstruction in a clean environment, and older reviews, preparation reports, and STATUS history retained outdated descriptions such as not started, unresolved, or not ready. The then-current README identified active work and unfinished final evaluation, and historical records were dated. The final index should still identify their historical role so file existence or old titles do not mislead. Human listening, MOS, speaker similarity, and full-run energy consumption lacked evidence and must remain explicitly unmeasured rather than fabricated to complete the deliverables.
